# v1.2 — Replay tools and simulation workspaces

The recorded-location rollout is the foundation: on-demand imports, PostgreSQL persistence, explicit coverage gaps, retry, and preserved replay state. Interlagos was upgraded live to 22 traces / 127,688 retained samples; bookmarks and the payload survived an API restart.

Five implemented upgrades for this release:

1. Clock-based trails for the selected and comparison drivers; gaps split the line and seeking never leaves future movement behind.
2. Shareable replay moments containing race, elapsed time, driver, comparison, speed and position source. Links reopen paused and validate inputs.
3. Multiple named map layouts per race, with load/delete and safe local storage handling.
4. A separate custom-track workspace with editable geometry, adjustable rounded corners, validation, local save/load, JSON export/import and a marker preview that follows the same curves.
5. A strategy what-if sandbox based on completed recorded laps, with explicit pace/pit/degradation assumptions and side-by-side projected outcomes.

Custom geometry and hypothetical results do not change historical replay data. Accounts, multiplayer, commercial launch, 3D cars and model upgrades remain later milestones.

Each increment gets unit/browser coverage appropriate to its behavior. The release is merged locally into `master`; publishing and GitHub CI are verified only after a successful authenticated push.

## Try it locally

1. Start Docker Compose or the development API/frontend as described in the README. Open Monza and jump to a lap with recorded coverage.
2. Choose 30-second **Driver trails**, then seek backwards or switch to **Lap estimate**. Trails follow the replay clock, show only the selected/comparison drivers that are visible, and disappear in estimate mode.
3. Open **Share moment**. Copy or open the generated link; it contains the race, time and controls and opens paused. Localhost links need the same computer. A different server may need to import timing first and may not have recorded positions cached.
4. Under **Drivers & view**, name a view and select **Save named layout**. Change the camera, choose the named view, and load it. Reusing a name replaces the saved entry. There are ten slots per race; **Save layout** independently sets your default view.
5. Open **Custom circuit studio**. Drag points or select one and use arrow keys; Shift moves in larger steps. Add/remove points, undo/redo, move start/finish, and choose ordered sector ends. **Corner rounding** changes the actual path and preview route; tight sections cap the rounding to avoid cutting across nearby edges. Control handles define the original corners. Save locally or export JSON; imports are validated and stay drafts until saved. Existing v1 files without a rounding field use a default of 28. The studio supports 6–120 points and up to 20 saved circuits.
6. Open **Strategy what-if lab**. Choose a driver, the completed lap to branch after, and a 1–40 lap horizon within the race's remaining laps. When the current moment is too early, the lab initially samples through lap 10 (or the latest possible branch for shorter races). The replay itself does not seek. Edit Plan A/B, inspect the graph and per-lap table, and save a named scenario or export the full comparison. Ten scenarios can be saved per race.

## Strategy assumptions

The base pace is a robust median from up to 12 recent usable laps ending at the branch point. Lap one, known pit in/out laps, and large timing outliers are excluded. At least three samples are needed. No later lap duration enters the calibration; the source sample range is shown so users can assess variability.

For each future lap, the model starts with sampled pace plus the plan's pace adjustment, then adds linear degradation. A stop adds pit loss once on its selected future lap. The following lap starts with zero incremental degradation and the assumed fresh-tyre gain relative to the sampled pace. Both plans use the same calibration.

The model excludes traffic, opponents, overtaking, fuel, weather, safety-car behavior, tyre-compound rules and failures. Samples can still include traffic/flag effects. A faster projected total does not imply an actual finishing position or an empirically proven alternative result. Hypothetical geometry and projections never replace historical timing or coordinates.

## Storage and checks

Recorded-location upgrades and bookmarks use PostgreSQL when configured. Named layouts, custom tracks and strategy scenarios are browser-local and report save failures without blocking playback. JSON exports are portable files, not uploaded content. There are no new accounts, external hosting services, paid integrations or commercial data claims in this release.

Validation includes 44 unit checks, five importer checks, 30 Chromium browser scenarios, and real ASP.NET/PostgreSQL integration checks with restart persistence. Browser tests use deterministic provider-job fixtures; live Interlagos coverage was verified separately. The repository's existing GitHub Actions pipeline runs these checks and builds the Docker image after publication.

## Publish the prepared release

The local release is merged into `master` and annotated as `v1.2.0`. From your own signed-in PowerShell, run:

```powershell
node scripts/push-github.mjs master feature/location-imports feature/replay-workspace
```

The helper includes reachable annotated tags and requests an atomic push, so the listed branches and release tag publish together or fail together. It never force-pushes. The Codex session cannot persist GitHub credentials through Windows Credential Manager; run this in your own Windows terminal. After the push, verify the GitHub Actions run for `master` before treating the hosted image as ready. `main` remains the repository's existing default branch; this release targets `master` as requested.
